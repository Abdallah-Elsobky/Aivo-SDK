📦 Step-by-Step Installation & Setup

Aivo SDK is built natively for Kotlin Multiplatform (KMP) and can be integrated into Android applications, KMP shared modules, iOS applications, or server-side JVM runtimes (e.g., Ktor, Spring Boot).

Step 1: Configure Repositories

In your root settings.gradle.kts, ensure mavenCentral() and google() are declared:

settings.gradle.kts 
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
    }
}

Step 2: Add Dependencies

// Android app/build.gradle.kts
dependencies {
    // Aivo SDK Universal Multiplatform Engine
    implementation("com.aivo:aivo-sdk:1.0.0")

    // Kotlin Coroutines & JSON Serialization
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.8.1")
    implementation("org.jetbrains.kotlinx:kotlinx-serialization-json:1.6.3")
}

Step 3: Acquiring & Storing API Keys Securely

Before making calls, acquire your API credentials from your preferred provider:

  • Ollama Cloud: Get your key from ollama.com. (Preconfigured Cloud Endpoint: https://ollama.com/api/chat).
  • Google Gemini: Generate a free API key at Google AI Studio.
  • OpenRouter: Generate an API key at openrouter.ai to access 200+ models.
🔐
Android Secret Storage Pattern: Never commit API keys to Git. Store your keys in local.properties (which is ignored by .gitignore):
OLLAMA_API_KEY=your_key_here
GEMINI_API_KEY=AIzaSy...

Then inject them into BuildConfig in app/build.gradle.kts:

app/build.gradle.kts 
android {
    defaultConfig {
        val properties = java.util.Properties()
        val localPropertiesFile = rootProject.file("local.properties")
        if (localPropertiesFile.exists()) {
            properties.load(localPropertiesFile.inputStream())
        }
        buildConfigField("String", "OLLAMA_API_KEY", "\"${properties.getProperty("OLLAMA_API_KEY", "")}\"")
        buildConfigField("String", "GEMINI_API_KEY", "\"${properties.getProperty("GEMINI_API_KEY", "")}\"")
    }
    buildFeatures {
        buildConfig = true
    }
}

🚀 Quick Start: 3 Levels of DX

Aivo SDK adapts cleanly to your application requirements with three distinct levels of Developer Experience (DX):

1️⃣
Level 1: Raw LLM
Zero orchestration overhead. Stream tokens directly or get single-turn completions using strongly-typed models.
2️⃣
Level 2: Autonomous Agent
Single agent armed with type-safe tools, JSON schema validation, reasoning loops, and human approval gates.
3️⃣
Level 3: Multi-Agent Team
Supervisor agent delegating tasks dynamically across specialized research, writing, and analysis agents.

Level 1: Raw LLM (Chat & Token Streaming)

RawLlmExample.kt 
val aivo = AivoSdk.create(
    provider = AivoProvider.OLLAMA,
    model    = OllamaModel.GPT_OSS_120B.modelId,
    apiKey   = BuildConfig.OLLAMA_API_KEY
)

// One-shot completion
val response = aivo.chat("Explain coroutines in 2 sentences")
println(response.text)

// Token-by-token streaming Flow
aivo.stream("Explain state machines")
    .collect { event ->
        if (event is AgentEvent.Delta) print(event.text)
    }

🛠️ Creating Tools & Safety Confirmation Gates

Tools empower your agents to take real-world actions: fetch weather APIs, query Room/SQLite databases, trigger device sensors, or execute transactions.

Step 1: Anatomy of a Tool

Use the type-safe tool("name", "description") { ... } DSL to define tools with strict parameter schemas:

WeatherTool.kt 
val getWeatherTool = tool("get_weather", "Fetches live weather conditions for a given city") {
    // 1. Declare JSON schema parameter constraints
    parameters {
        string("city", "The city name", required = true, minLength = 2)
        string("unit", "Temperature unit", required = false, enum = listOf("celsius", "fahrenheit"))
        boolean("forecast", "Include 3-day forecast", required = false)
    }

    // 2. Execute business logic with type-safe extractors
    execute { args ->
        val city = args.string("city")
        val unit = args.stringOrNull("unit") ?: "celsius"
        val isForecast = args.booleanOrNull("forecast") ?: false
        
        // Call your real backend or network service
        """{"city": "$city", "temp": 24, "unit": "$unit", "condition": "Sunny"}"""
    }
}

Step 2: Safety & Human Confirmation Gates (High-Risk Tools)

When a tool performs sensitive mutations (e.g., spending money, deleting files, sending emails), you must protect against autonomous hallucinations using Human Confirmation Gates:

TransferMoneyTool.kt 
val transferFundsTool = tool("transfer_funds", "Transfers funds between bank accounts") {
    riskLevel = RiskLevel.HIGH
    requireConfirmation = true  // Runtime pauses and emits RequiresConfirmation event

    parameters {
        string("fromAccount", "Debiting account", required = true)
        string("toAccount", "Crediting account", required = true)
        double("amount", "Transfer amount in USD", required = true, minimum = 1.0)
    }

    execute { args ->
        val from = args.string("fromAccount")
        val to = args.string("toAccount")
        val amount = args.double("amount")
        bankApi.transfer(from, to, amount)
        "Successfully transferred $$amount from $from to $to"
    }
}

When the LLM invokes this tool, the SDK execution loop pauses and emits AgentEvent.RequiresConfirmation containing the tool name, arguments, and a unique toolCallId. The app UI prompts the user (e.g. via biometric dialog), and then confirms or rejects:

ConfirmationApproval.kt 
// When user taps "Approve" in Compose Dialog:
runtime.confirm(toolCallId = event.toolCallId, approved = true)

// Or if user rejects:
runtime.confirm(toolCallId = event.toolCallId, approved = false, reason = "User cancelled transfer")

🤖 Creating Single Agents & Giving Them Tools

An Agent combines a persona/role, instructions (system prompt), scoped tools, and execution limits.

Step 1: Programmatic Agent in Kotlin DSL

Register tools globally, then scope specific tools to your agent:

SingleAgentSetup.kt 
val aivo = AivoSdk {
    providers {
        ollama(AivoProvider.OLLAMA.id) { apiKey(BuildConfig.OLLAMA_API_KEY) }
    }
    defaultModel(OllamaModel.GPT_OSS_120B)

    // 1. Register available tools
    tools {
        +getWeatherTool
        +transferFundsTool
    }

    // 2. Define the Agent and assign scoped tools
    agents {
        define("concierge") {
            name = "Personal Concierge"
            systemPrompt = """
                You are a helpful mobile concierge.
                Customer Name: {{user_name}}
                Always check weather before suggesting outdoor activities.
            """.trimIndent()
            
            // Give specific tools to this agent
            tools("get_weather")
            
            // Set maximum execution turns to prevent infinite loops
            maxSteps = 10
        }
    }
    entryAgent("concierge")
}

// 3. Execute with dynamic prompt variables
val response = aivo.chat(
    message   = "What should I wear today in Cairo?",
    variables = mapOf("user_name" to "Abdallah")
)
println(response.text)

👥 Creating Multi-Agent Teams & The Supervisor Pattern

Monolithic prompts struggle with complex multi-step workflows. Multi-agent teams solve this through specialization of labor:

👑
Supervisor Agent
Coordinates incoming goals, plans sub-tasks, dispatches work to specialists, and synthesizes the final response.
🔎
Researcher Specialist
Armed exclusively with search & database tools to gather factual insights without hallucinating opinions.
✍️
Writer Specialist
Takes gathered research and writes structured, publication-grade markdown reports without needing tool access.

Full Multi-Agent Team Setup with Blackboard State

Agents share structured findings without string collisions using strongly-typed StateKey<T>:

MultiAgentTeamExample.kt 
// 1. Define strongly-typed shared keys for inter-agent communication
object TeamKeys {
    val ResearchFindings = StateKey.string("research_findings")
    val DraftSummary = StateKey.string("draft_summary")
}

// 2. Build the Multi-Agent Team
val marketReportTeam = team("MarketAnalysisTeam") {
    
    // Supervisor coordinates the workflow
    supervisor {
        name = "Lead Coordinator"
        systemPrompt = "Analyze the user prompt. First delegate research to 'researcher'. Then delegate reporting to 'writer'."
        model(AivoProvider.OLLAMA, OllamaModel.GPT_OSS_120B.modelId)
    }

    // Specialist 1: Researcher (has web search tool)
    agent("researcher") {
        name = "Market Researcher"
        systemPrompt = "Extract key verified industry statistics and write notes into the blackboard."
        tools("web_search")
        model(AivoProvider.OLLAMA, OllamaModel.GPT_OSS_120B.modelId)
    }

    // Specialist 2: Writer (synthesizes findings)
    agent("writer") {
        name = "Executive Writer"
        systemPrompt = "Read research findings and format a bulleted executive briefing."
        model(AivoProvider.OLLAMA, OllamaModel.GPT_OSS_120B.modelId)
    }
}

// 3. Execute the collaborative workflow
val finalBriefing = marketReportTeam.execute("Analyze renewable energy battery storage growth in 2026")
println(finalBriefing.text)

🌊 Reactive Streaming in Jetpack Compose & iOS

Provide instant feedback to users by streaming tokens as they generate, showing tool progress chips, and handling confirmation dialogs.

1. Jetpack Compose ViewModel

ChatViewModel.kt 
data class MessageUi(val sender: String, val text: String, val isToolExecuting: Boolean = false)

class ChatViewModel(private val aivo: AivoSdk) : ViewModel() {
    private val _messages = MutableStateFlow>(emptyList())
    val messages: StateFlow> = _messages.asStateFlow()

    // Confirmation gate state for UI Dialog
    var pendingConfirmation by mutableStateOf(null)
        private set

    fun sendMessage(prompt: String) {
        _messages.update { it + MessageUi(sender = "User", text = prompt) }
        _messages.update { it + MessageUi(sender = "Assistant", text = "") }

        viewModelScope.launch {
            aivo.stream(prompt).collect { event ->
                when (event) {
                    is AgentEvent.Delta -> {
                        _messages.update { list ->
                            val last = list.last()
                            list.dropLast(1) + last.copy(text = last.text + event.text)
                        }
                    }
                    is AgentEvent.ToolStarted -> {
                        _messages.update { list ->
                            val last = list.last()
                            list.dropLast(1) + last.copy(isToolExecuting = true)
                        }
                    }
                    is AgentEvent.ToolCompleted -> {
                        _messages.update { list ->
                            val last = list.last()
                            list.dropLast(1) + last.copy(isToolExecuting = false)
                        }
                    }
                    is AgentEvent.RequiresConfirmation -> {
                        pendingConfirmation = event // Triggers Compose alert dialog
                    }
                    is AgentEvent.Completed -> { /* Stream finished */ }
                    is AgentEvent.Error -> { /* Handle error */ }
                    else -> Unit
                }
            }
        }
    }

    fun handleConfirmation(approved: Boolean) {
        val event = pendingConfirmation ?: return
        aivo.confirm(event.toolCallId, approved)
        pendingConfirmation = null
    }
}

2. Jetpack Compose UI Screen

ChatScreen.kt 
@Composable
fun ChatScreen(viewModel: ChatViewModel = viewModel()) {
    val messages by viewModel.messages.collectAsState()
    var input by remember { mutableStateOf("") }

    // Human Confirmation Dialog Gate
    viewModel.pendingConfirmation?.let { conf ->
        AlertDialog(
            onDismissRequest = { viewModel.handleConfirmation(false) },
            title = { Text("Approve Action: ${conf.toolName}") },
            text = { Text("Parameters: ${conf.arguments}") },
            confirmButton = {
                Button(onClick = { viewModel.handleConfirmation(true) }) { Text("Approve") }
            },
            dismissButton = {
                OutlinedButton(onClick = { viewModel.handleConfirmation(false) }) { Text("Reject") }
            }
        )
    }

    Column(modifier = Modifier.fillMaxSize().padding(16.dp)) {
        LazyColumn(modifier = Modifier.weight(1f)) {
            items(messages) { msg ->
                ChatBubble(msg)
            }
        }
        Row(modifier = Modifier.fillMaxWidth()) {
            TextField(
                value = input,
                onValueChange = { input = it },
                modifier = Modifier.weight(1f),
                placeholder = { Text("Ask Aivo...") }
            )
            Button(onClick = { 
                viewModel.sendMessage(input)
                input = "" 
            }) { Text("Send") }
        }
    }
}

🧠 Persistent Memory & Context Strategies

Control how conversation history is persisted across mobile sessions and prevent model context limit overflows:

Sliding Window
Retains the most recent $N$ messages (e.g. maxMessages = 20) while always preserving the system instructions.
Token Budget
Estimates tokens backwards from newest to oldest until a threshold (e.g. maxTokens = 8_000) is reached.
The Atomic Tool Pairing Invariant
Tool calls and their corresponding execution results are grouped as atomic units. They are never orphaned, preventing provider rejection errors.
MemorySetup.kt 
val aivo = AivoSdk {
    // ...
    memory {
        // Option A: In-memory sliding window
        slidingWindow(maxMessages = 20)
        
        // Option B: Token budget with character heuristic
        tokenBudget(maxTokens = 8_000, estimator = CharCountEstimator)
    }
}

🛡️ Resilience, Guardrails & Security

Production AI must be fortified against unstable connections, runaway execution costs, and data leaks:

  • Exponential Backoff with Jitter: Automatically retries 429 Rate Limit and 503 Server Unavailable errors with exponential delays (1s, 2s, 4s).
  • Strict Execution Bounds: Every agent has a hard limit (e.g. maxSteps = 15). If an agent exceeds this, it terminates cleanly instead of burning tokens indefinitely.
  • Secret Redaction Filter: Telemetry and logs automatically mask API keys, tokens, and credit card numbers using regex sanitization before output.
  • Concurrency Mutex: Memory store operations use Kotlin Coroutine Mutexes to guarantee thread-safe state mutations across parallel agent turns.

// 4. Reactive Jetpack Compose ViewModel
class TravelViewModel : ViewModel() {
    private val _messages = MutableStateFlow<List<String>>(emptyList())
    val messages: StateFlow<List<String>> = _messages.asStateFlow()

    private val _pendingGate = MutableStateFlow<AgentEvent.RequiresConfirmation?>(null)
    val pendingGate: StateFlow<AgentEvent.RequiresConfirmation?> = _pendingGate.asStateFlow()

    fun bookTrip(prompt: String) {
        viewModelScope.launch {
            aivo.stream(prompt).collect { event ->
                when (event) {
                    is AgentEvent.Delta -> {
                        _messages.update { it + event.text }
                    }
                    is AgentEvent.RequiresConfirmation -> {
                        // Triggers Biometric / Dialog Confirmation in Compose UI
                        _pendingGate.value = event
                    }
                    is AgentEvent.Completed -> {
                        println("Workflow finished! Usage: \${event.usage.totalTokens} tokens")
                    }
                    is AgentEvent.Error -> {
                        println("Workflow error: \${event.error.message}")
                    }
                    else -> Unit
                }
            }
        }
    }

    fun approveAction(approved: Boolean) {
        val event = _pendingGate.value ?: return
        aivo.confirm(event.toolCallId, approved)
        _pendingGate.value = null
    }
}

🏛️ 4-Layer Clean Architecture & Module Matrix

Aivo SDK strictly follows Clean Architecture and SOLID principles. The inward dependency rule ensures sdk-core never references Ktor, HTTP, or JSON wire schemas:

Layer Gradle Module Key Responsibilities Inward Dependencies
Layer 1: Core Domain sdk-core Domain models (LlmRequest, Agent, Tool), interfaces (LlmProvider, MemoryStore) Zero (pure Kotlin only)
Layer 2: Transport sdk-transport Ktor HTTP client, custom SseDecoder, frame buffering, retry middleware sdk-core
Layer 3: Providers sdk-provider-* WireProtocols for Ollama, Gemini Interactions, OpenRouter, and OpenAI-compatible sdk-core, sdk-transport
Layer 4: Runtime sdk-runtime Reasoning loops, supervisor delegation, memory engines, telemetry sdk-core, sdk-middleware

🗂️ File Inventory & Core Architectural Invariants

To maintain consistency across Android, iOS, and JVM targets, every contributor must uphold five non-negotiable architectural invariants:

🔒
Invariant #1 (Zero Reflection): No JVM reflection (Class.forName, java.lang.reflect) is allowed in commonMain to ensure flawless compilation on iOS Native.
⚡
Invariant #2 (Pure Core Domain): sdk-core must never import Ktor or JSON wire serializer annotations. All HTTP transport concerns belong in sdk-transport.

🔄 Execution Lifecycles & Architecture Flowcharts

This section provides core contributors with an in-depth visual map of how requests, token streams, tool executions, and multi-agent handoffs flow through the Aivo SDK engine.

🌊 Flow 1: End-to-End Reactive Streaming Pipeline
Runtime Architecture
STEP 1 • CLIENT ENTRYPOINT
Client Calls aivo.stream(prompt)
Android ViewModel or iOS Swift controller triggers reactive stream. Runtime allocates a coroutine scope and resolves conversation memory.
STEP 2 • DOMAIN TO WIRE ENCODING
WireProtocol.encodeRequest(LlmRequest)
The provider's WireProtocol transforms pure Kotlin domain models into provider-specific JSON payloads (e.g. Ollama /api/chat or Gemini /v1beta/interactions).
STEP 3 • NETWORK & CUSTOM SSE DECODER
Ktor HttpClient POST & SseDecoder Line Buffer
HTTP POST request streams byte chunks across Darwin/OkHttp engine. Zero-dependency SseDecoder handles CRLF normalization, strips comments, and buffers partial frames.
STEP 4 • REACTIVE UI DISPATCH
Flow<AgentEvent.Delta> Emits to UI
Parsed text tokens emit into Jetpack Compose StateFlow with sub-millisecond latency. Token usage metrics and stream completion emit upon closing.
🛡️ Flow 2: Tool Execution & Safety Confirmation Gate
Safety Guardrail
PHASE A • INVOCATION DETECTION
LLM Emits ToolCall(name, arguments)
Model streams tool call token. Reasoning loop pauses token output and validates arguments against the registered JSON Schema parameters.
PHASE B • RISK EVALUATION GATE
Risk Assessment & Human Approval Gate
• Low Risk: Executes immediately in coroutine worker.
• High Risk / requireConfirmation: Emits AgentEvent.RequiresConfirmation(toolCallId) and suspends until client invokes runtime.confirm().
PHASE C • ATOMIC MEMORY COMMIT
Atomic Tool Pairing Invariant Commit
Tool result is formatted as Message.Tool. Assistant call and tool response are written atomically to memory under a Mutex lock to prevent orphaned message states.
👑 Flow 3: Multi-Agent Supervisor & Blackboard State Loop
Orchestration
STEP 1 • SUPERVISOR DECONSTRUCTION
Supervisor Receives User Goal & Plans Execution
Supervisor agent analyzes inquiry complexity, checks current shared BlackboardState, and chooses the optimal specialist agent.
STEP 2 • SPECIALIST WORKER EXECUTION
Specialist Agent Runs Scoped Capabilities
Researcher agent executes search tools; findings are written directly to strongly-typed blackboard keys (e.g. StateKey.string("findings")).
STEP 3 • SYNTHESIS & HANDOFF
Supervisor Review or Delegation to Next Specialist
Supervisor evaluates output against maxSteps limit. If complete, synthesizes final executive brief and returns answer to user.

🧩 Extending the SDK: Adding Providers & WireProtocols

Adding support for a new model provider (e.g. Mistral or Anthropic) requires only implementing the WireProtocol interface:

MistralWireProtocol.kt 
class MistralWireProtocol : WireProtocol {
    override fun encodeRequest(request: LlmRequest): HttpRequestPayload {
        return HttpRequestPayload(
            path = "/v1/chat/completions",
            body = buildJsonPayload(request)
        )
    }

    override fun decodeStreamFrame(frame: RawFrame): LlmStreamEvent? {
        return when (frame) {
            is RawFrame.Data -> parseDelta(frame.text)
            is RawFrame.Done -> LlmStreamEvent.Completed
        }
    }
}

HTTP 401 Unauthorized Missing or expired token Inspect local.properties; ensure BuildConfig.OLLAMA_API_KEY is injected.
HTTP 429 Rate Limit Provider quota exceeded Configure RetryPolicy.exponentialBackoff(maxRetries = 3, baseDelayMs = 1000).
SSE Stream Drops Prematurely Aggressive timeout or line buffering split Ensure SseDecoder buffers partial lines; bump Ktor socket timeout to 60s.
Tool Schema Rejection JSON parameter mismatch Verify parameter names declared in parameters { } match LLM output keys exactly.

🤝 Contributing Guidelines & Quality Bar

Help us build the most reliable agentic SDK in the Kotlin ecosystem. All pull requests must adhere to our contribution principles:

  • Follow Conventional Commits (e.g. feat: add mistral provider, fix: sse crlf buffer split).
  • Maintain Zero Reflection in commonMain for iOS Kotlin/Native compatibility.
  • Write automated offline unit tests using FakeLlmProvider and MockEngine.
  • Update corresponding documentation in docs/user-guide/ or docs/dev/ for all new public APIs.
